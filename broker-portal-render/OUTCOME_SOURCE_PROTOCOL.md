# Actual Outcome Source Protocol

Protocol version: **OSP-W37-2026-v1.0**
Baseline: **W37-2026-v0.1**
Baseline commit: `611f7e77f759265ae1ef59aec41fbe056de66645`

## Purpose
This protocol defines, before performance is evaluated, what may be recorded as an `Actual` market outcome for the W37 dry-bulk broker-validation pilot. It prevents post-hoc selection of the source or calculation method based on whether the model or a broker performed better.

## Non-negotiable rules
1. Model outputs can never be an Actual source.
2. A blind response submitted by a participating validation broker can never, by itself, be used as the Actual for the same case.
3. Every Actual entry must have an attributable source, observation timestamp, source reference, source tier and protocol version.
4. The ledger is append-only. Corrections supersede a prior entry; they never overwrite it.
5. The latest non-rejected ledger entry is the operative Actual for metrics, but the full history remains auditable.
6. If a source publishes a range only, the default Actual midpoint is the arithmetic midpoint `(low + high) / 2`. Any different methodology must be explicitly documented before insertion.
7. If a source gives an explicit midpoint plus a range, the published midpoint is used, provided it lies within the published range.
8. Currency/unit must be USD/mt for this pilot. Any conversion must be documented in `methodology` and the original value retained in `notes` or `source_ref`.

## Source hierarchy

### Tier 1 — CONFIRMED_FIXTURE
A completed or firmly reported fixture matching the case route, cargo-size band, vessel class and relevant market window.

Acceptance requirements:
- attributable fixture/source reference;
- sufficiently close route and cargo/vessel characteristics;
- timestamp after the model baseline was locked;
- no evidence the value was generated from this model.

Use: preferred Actual whenever available.

### Tier 2 — INDEPENDENT_PUBLISHED_ASSESSMENT
A post-lock published freight assessment or weekly market report from an independent market source, broker report or market-intelligence provider that covers the same route/size class.

Acceptance requirements:
- publication/reference retained;
- observed/publication timestamp retained;
- route and size mapping documented where not exact.

Use: preferred when no Tier-1 fixture is available.

### Tier 3 — MULTI_SOURCE_CONSENSUS
Consensus constructed from at least two independent post-lock observations that were not generated by the model and are not duplicate copies of the same upstream source.

Calculation rule:
- use the median of source midpoints;
- for an even number of sources, use the mean of the two central values;
- store the component sources in `source_ref`/`notes`.

Use: fallback when no Tier-1 or Tier-2 source exists.

### Tier 4 — SINGLE_INDEPENDENT_MARKET_OBSERVATION
One independent post-lock broker or market observation, provided that broker's blind validation response for the same case is not being reused as Actual.

Use: provisional only. It may be superseded if a higher-tier source later becomes available.

## Disallowed sources
- TRUSTION/Freight Intelligence model output or derived values.
- The participating broker's own blind submission for the same case.
- An unattributed chat/message with no timestamp or provenance.
- A source created after inspecting comparative model-vs-broker performance specifically to favor one side.
- A value outside the relevant route/size/window without an explicit mapping methodology.

## Range and midpoint policy
- Exact fixture: `actual_mid = fixture rate`; `actual_low` and `actual_high` may equal the same value or remain null.
- Published range without midpoint: `actual_mid = (actual_low + actual_high)/2`.
- Published range with midpoint: use the source midpoint if it lies inside the source range.
- Consensus: `actual_mid = median(component midpoints)`; `actual_low = min(component lows/mids)` and `actual_high = max(component highs/mids)` when available.

## Source selection rule
For each case, select the highest available source tier using this order: **Tier 1 > Tier 2 > Tier 3 > Tier 4**. Do not select between sources of different tiers based on which one produces a better model or broker score.

If multiple eligible sources exist in the same tier, use the one with the closest route/cargo/vessel match. If still tied, use the earliest independently published observation after the relevant market window. Document the tie-break decision.

## Corrections
A correction creates a new append-only row with `supersedes_id` pointing to the prior row. The reason for correction must be entered in `notes`. Historical rows remain immutable.

## Metrics eligibility
An Actual is eligible for headline Model-vs-Broker metrics only when:
- protocol version is `OSP-W37-2026-v1.0`;
- source tier is 1, 2 or 3;
- source is not disallowed;
- the case belongs to baseline `W37-2026-v0.1`.

Tier-4 observations are reported separately as provisional sensitivity evidence and must not be mixed into headline accuracy claims unless explicitly labeled.
